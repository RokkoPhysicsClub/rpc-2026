1. MDXって何？

1.1 まずMarkdownとは？

Markdown（マークダウン）は、文章に記号を少し付けるだけで、見出し・太字・リンクなどを表現できる書き方です。

たとえば、

# 物理部の活動報告

今日は実験をしました。

**とても面白かったです！**

と書くと、Webページではおおむね次のように表示されます。

物理部の活動報告

今日は実験をしました。

とても面白かったです！

つまり、

Markdown = 「文章を簡単な記号で構造化する方法」

と考えると分かりやすいです。

1.2 MDXとは？

MDXは簡単にいうと、

Markdown + JSX

です。

Markdownの書きやすさを保ちながら、Webページの部品（コンポーネント）などを文章の中に組み込めます。

たとえば、普通のMarkdownでは、

# 実験結果

実験が成功しました。

のような文章を書きます。

MDXでは、それに加えて、

# 実験結果

実験が成功しました。

<Notice>
これは重要なお知らせです。
</Notice>

のような書き方ができます。

ただし、どんなコンポーネントが使えるかはホームページ側の設定によって異なります。

そのため、このガイドでは、

  • ほぼどのMarkdown/MDX環境でも使える基本
  • サイトによって使えるか変わる発展機能

を分けて説明します。

1.3 .md と .mdx の違い

拡張子主な用途
.txt普通のテキスト
.mdMarkdown
.mdxMarkdown + JSX
.htmlHTMLでWebページを書く

.mdx は「Markdownのちょっと強化版」と考えても、最初のうちは問題ありません。

2. まず覚えるMarkdown

部誌を書くために、最初から全部覚える必要はありません。

まずはこのあたりを覚えれば十分です。

# 見出し

**太字**

*斜体*

- 箇条書き

1. 番号付きリスト

[リンク](https://example.com)

![画像の説明](image.jpg)

> 引用

`コード`

| 項目 | 値 |
|---|---|
| 長さ | 20 cm |

これだけでも、かなりちゃんとした記事を書けます。

3. 見出し

見出しは # を使います。

# 大見出し
## 中見出し
### 小見出し
#### さらに小さい見出し

# が少ないほど大きな見出しになります。

3.1 記事ではどう使う？

たとえば、

# 単振り子の周期を測定してみた

## はじめに

## 実験方法

## 結果

## 考察

## まとめ

のようにします。

おすすめ

基本的には、

  • # → 記事タイトル
  • ## → 大きな章
  • ### → 章の中の項目

という使い方にすると読みやすいです。

4. 段落と改行

普通に文章を書けば段落になります。

今日は物理室で実験をしました。

とても面白い結果が得られました。

空行を入れると、別の段落になります。

4.1 改行したい場合

Markdownでは、環境によって改行の扱いが少し違います。

一般的には、

1行目  
2行目

のように行末に半角スペースを2個置く方法があります。

ただし、ホームページ側の設定によって挙動が異なることがあります。

「改行したのに改行されない！」となったら、まず空行を入れて段落を分けてみましょう。

7. リンク

リンクは、

[表示する文字](URL)

と書きます。

例：

[物理部ホームページ](https://example.com)

表示：

物理部ホームページ

※実際のホームページでは、学校や部のサイトのURLに置き換えてください。

7.1 メールアドレスなど

Markdown環境によっては、

<example@example.com>

のような書き方もできます。

ただし、部誌では個人のメールアドレスなどを不用意に公開しないようにしましょう。

8. 画像

画像は、

![画像の説明](画像ファイルの場所)

と書きます。

例：

![実験装置](./images/device.jpg)

ここで、

  • ![...] → 画像の説明
  • (...) → 画像ファイルの場所

です。

8.1 画像の説明はなぜ必要？

この部分、

![実験装置](./images/device.jpg)

の「実験装置」は、画像が表示されない場合などに役立ちます。

また、アクセシビリティ（画面読み上げなど）の面でも重要です。

8.2 写真を載せるときの注意

部誌に写真を載せるときは、

  • 人の顔が写っていないか
  • 名前や学校名などが写り込んでいないか
  • 個人情報が写っていないか
  • 他人の作品や資料を無断で掲載していないか

を確認しましょう。

「撮った写真だから何でも載せてOK」ではありません。

9. 引用

他の文章を引用するときは > を使います。

> これは引用です。

表示：

これは引用です。

複数行なら、

> 1行目
> 2行目
> 3行目

のようにします。

9.1 引用と自分の文章を区別する

誰かの発言・資料・本などを引用する場合は、

  • どこから引用したか
  • 誰が書いたか
  • 必要ならURLや資料名

を分かるようにしましょう。

引用した文章を、自分が書いた文章のように見せないことが重要です。

コードとしてそのまま表示されます。

13. HTML

MDXではHTMLのようなタグを書ける場合があります。

<p>これはHTMLの段落です。</p>

HTMLでは、

<strong>太字</strong>

のようなタグもあります。

ただし、

「MarkdownでできることはMarkdownで書く」

のがおすすめです。

たとえば、

**太字**

で済むなら、

<strong>太字</strong>

と書く必要はありません。

HTMLを多用すると、記事が読みにくくなります。

14. MDXならではの機能

ここからがMDXらしい部分です。

MDXでは、Markdownの中にJSXを書けます。

たとえば、

<Notice>
これは重要なお知らせです。
</Notice>

のような記述ができます。

ただし、ここで注意。

14.1 すべてのタグが使えるわけではない

ホームページ側に、

Notice

というコンポーネントが登録されていなければ、

<Notice>
...
</Notice>

は使えません。

つまり、

MDXの文法として書けること

と

このホームページで実際に使えること

は別問題です。

この違いは非常に重要です。

15. JSXとコンポーネント

15.1 JSXとは？

JSXは、JavaScriptの中にHTMLのような記法を書ける仕組みです。

MDXでは、この仕組みを使ってWebページの部品を配置できます。

例えば、

<MyComponent />

のような記述です。

15.2 コンポーネントとは？

ざっくり言えば、

何度も使えるWebページの部品

です。

例えばホームページ側で、

Notice

という「注意書きボックス」を作っておけば、

<Notice>
実験を行うときは安全に注意してください。
</Notice>

と書くだけで同じデザインの注意書きを表示できる、という仕組みです。

15.3 属性を渡す

コンポーネントには値を渡せる場合があります。

<Experiment
  name="単振り子"
  period={2.01}
/>

ここでは、

  • name → "単振り子"
  • period → 2.01

という値を渡しています。

ただし、実際にどんな属性を受け取れるかは、そのコンポーネントを作った人次第です。

16. JavaScriptの値を使う

MDXでは、環境によってJavaScriptの式を {} の中に書けます。

例えば、

{2 + 3}

なら、環境によっては、

5

と表示されます。

16.1 変数

例えば、

const temperature = 25.4

のようなMDX/JavaScript構文をサポートする環境では、

温度は {temperature} ℃ です。

のように書ける場合があります。

しかし、ここはサイトのMDX実装によって違うため、部誌執筆者は無理に使う必要はありません。

16.2 {} に注意

MDXでは { と } が特別な意味を持つことがあります。

例えば、

温度は {25} ℃

は単なる文章ではありません。

普通の文章として波括弧を表示したい場合は、サイトの仕様に合わせたエスケープなどが必要になることがあります。

困ったら、まずその部分を削って、どこでエラーが出ているか確認しましょう。

17. 数式

物理部の記事では数式を書きたくなることがあります。

例えば、

$$ F = ma $$

や、

$$ E = mc^2 $$

などです。

ただし、数式が使えるかどうかはホームページ側の設定次第です。

KaTeXやMathJaxなどの数式表示機能が設定されている場合に、

$$
F = ma
$$

のような書き方が使えることがあります。

17.1 インライン数式

環境によっては、

質量を $m$、加速度を $a$ とすると、
力は $F=ma$ です。

のように書けます。

17.2 よく使う数式

二次方程式

x = (-b ± √(b² - 4ac)) / 2a

運動方程式

F = ma

運動エネルギー

E = 1/2 mv²

重力による位置エネルギー

E = mgh

オームの法則

V = IR

17.3 数式機能が使えない場合

無理に数式記法を使わなくても大丈夫です。

例えば、

F = ma

と普通に書く方法もあります。

重要なのは、

読者が意味を理解できること

です。

18. Frontmatter

MDXファイルの最初に、

---
title: "単振り子の実験"
description: "単振り子の周期を測定した実験の記録"
---

のような部分があることがあります。

これを一般に Frontmatter と呼びます。

18.1 何に使うの？

Frontmatterには記事の情報を入れます。

例えば、

---
title: "単振り子の周期を測定してみた"
author: "物理部"
date: "2026-09-06"
---

などです。

ホームページ側が対応していれば、

  • 記事タイトル
  • 作者
  • 日付
  • 説明
  • カテゴリ
  • タグ

などとして利用できます。

18.2 重要な注意

Frontmatterで使える項目はホームページ側の設定次第です。

例えばサイトが author に対応していなければ、

author: "物理部"

と書いても何も起こらない可能性があります。

つまり、

サンプル記事に書かれているFrontmatterを基本的には真似する

のが安全です。

19. 記事を書くときの基本構成

物理部の記事では、次のような構成がおすすめです。

タイトル
↓
はじめに
↓
目的
↓
仮説
↓
実験方法
↓
結果
↓
考察
↓
まとめ

もちろん、すべての記事でこの形にする必要はありません。

19.1 「はじめに」

なぜこの実験・活動をしたのかを書きます。

例：

## はじめに

今回は、振り子の長さによって周期が
どのように変化するのかを調べました。

19.2 「目的」

何を調べたいのかを明確にします。

## 目的

振り子の長さと周期の関係を調べることを目的としました。

19.3 「仮説」

実験前にどう予想したかを書きます。

## 仮説

振り子が長くなるほど、
1往復にかかる時間も長くなると予想しました。

19.4 「実験方法」

読んだ人が実験の内容を理解できるように書きます。

## 実験方法

1. 糸におもりを取り付ける。
2. 糸の長さを測定する。
3. おもりを小さな角度で振る。
4. 10往復する時間を測定する。
5. 糸の長さを変えて同じ測定を行う。

19.5 「結果」

測定値を載せます。

## 結果

| 長さ | 10往復の時間 |
|---:|---:|
| 20 cm | 8.9 s |
| 40 cm | 12.7 s |
| 60 cm | 15.6 s |

19.6 「考察」

「結果から何が分かったか」を書きます。

ここでは、

結果 → なぜそうなった？ → 仮説と合っている？ → 誤差は？

という流れで考えると書きやすいです。

19.7 「まとめ」

記事全体を短くまとめます。

## まとめ

今回の実験では、振り子の長さが長くなるほど
周期も長くなる傾向が確認できました。

21. よくあるミス

21.1 # の後ろにスペースを入れ忘れる

これは、

#タイトル

ではなく、

# タイトル

とするのが基本です。

21.2 バッククォートを間違える

コードブロックでは、


という **バッククォート（`）を3個**使います。

シングルクォート `'` とは別物です。

---

## 21.3 ファイルの場所を間違える

画像が、

```text
images/device.jpg

にあるのに、

![実験装置](device.jpg)

と書くと、表示できない場合があります。

画像の場所を確認しましょう。

21.4 全角記号を使ってしまう

例えば、

＃ 見出し

の ＃ は全角です。

Markdownの記号は基本的に半角を使います。

# 見出し

21.5 < や > に注意

MDXでは、

<
>
{
}

などが特別な意味を持つ場合があります。

普通の文章で使っただけなのにエラーになったら、このあたりを疑いましょう。

21.6 MarkdownのサイトとMDXのサイトは完全には同じではない

「ネットで見つけたMarkdownの書き方を全部試したら動く」

とは限りません。

Markdownにもいくつかの仕様・実装がありますし、MDXではさらにサイト側の設定が関係します。

サンプル記事があるなら、それを一番の見本にしてください。

22. 困ったときのチェックリスト

記事が表示されないときは、上から順番に確認しましょう。

ファイル

  • 拡張子が .mdx になっている
  • ファイル名に変な文字が入っていない
  • 正しいフォルダに入っている

Markdown

  • # の後ろにスペースがある
  • ** や ` の閉じ忘れがない
  • リンクの []() が正しい
  • 画像のパスが正しい

MDX

  • <Component> の閉じ忘れがない
  • {} の閉じ忘れがない
  • 存在しないコンポーネントを使っていない

Frontmatter

  • ファイル先頭にある
  • --- が正しく2回ある
  • サイトが対応している項目だけ使っている

23. 用語集

Markdown

文章を簡単な記号で構造化して書くための記法。

MDX

MarkdownにJSXなどの機能を組み合わせた形式。

JSX

JavaScript/React系で使われる、HTMLに似た記法。

React

Webページを部品（コンポーネント）単位で作るためのJavaScriptライブラリ。

コンポーネント

Webページの中で再利用できる部品。

Frontmatter

Markdown/MDXファイルの先頭に書くメタデータ。

Markdownパーサー

MarkdownをHTMLなどに変換するプログラム。

レンダリング

書いた文章やコードを、実際に画面に表示できる形にすること。

拡張子

ファイル名の最後に付いている .md や .mdx などの部分。

24. 発展編

ここからは「もっと知りたい人」向けです。

24.1 MDXはただの文章ファイルではない

Markdownは基本的に、

文章
↓
Markdownとして解釈
↓
HTMLなどへ変換

という流れです。

MDXでは、そこにコンポーネントやJavaScriptなどが加わります。

MDX
 ↓
MDXの解析
 ↓
Markdown + JSXなどを処理
 ↓
Webページの部品としてレンダリング
 ↓
ブラウザに表示

だから、

「Markdownなのに、なんで <Something /> が出てくるの？」

という疑問が生まれます。

答えは、

MDXはMarkdownだけではなく、JSXを扱えるようにした形式だから

です。

24.2 MDXはプログラミング言語なの？

厳密には「MDXファイルを書いている = JavaScriptプログラムを書いている」という単純な話ではありません。

しかし、MDXではJavaScript/JSXの機能と組み合わせられるため、普通のMarkdownよりずっとプログラムに近いことができます。

初心者のうちは、

Markdown = 文章を書く

MDX = 文章を書く + Web部品も使える

くらいの理解で十分です。

24.3 Markdown記法を全部暗記する必要はない

これはかなり大事です。

暗記する必要はありません。

よく使うものだけ覚えて、

# 見出し
**太字**
- リスト
[リンク](URL)
![画像](画像)
> 引用

あとは必要なときにこのガイドを見る、でOKです。

プログラマーも記法を全部暗記しているわけではありません。

24.4 良い記事を書くコツ

技術的に正しいだけではなく、

「読んだ人が分かるか？」

を意識しましょう。

例えば、

実験しました。

だけより、

## 実験方法

振り子の長さを20 cm、40 cm、60 cmに変え、
それぞれ10往復する時間を測定しました。

の方が圧倒的に分かりやすいです。

24.5 数字には単位を付ける

物理の記事では特に重要です。

悪い例：

長さは20でした。

良い例：

長さは20 cmでした。

さらに、

時間は2.4 sでした。

のように単位を明記しましょう。

24.6 結果と考察を分ける

これは実験記事では重要です。

結果

「何が測定されたか」

考察

「なぜその結果になったと考えられるか」

例えば、

結果：
温度が10分間で24.0 ℃から28.5 ℃に上昇した。

考察：
装置が動作すると発生した熱によって、
周囲の温度が上昇した可能性がある。

というように分けます。

ここまで読めば、物理部の部誌を書くための基本はかなり押さえられています。

もう一度、最低限必要なものだけまとめます。

これだけ覚えれば記事を書ける！
